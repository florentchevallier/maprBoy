# maprBoy — Project Notes

Working notes and history of the project. Kept for the project history: they explain **why** things are the way they are. For how to use the tool, see `README.md`; for technical details of the pipeline, see `docs/PIPELINE.md`.

The project builds custom maps for **Wahoo ELEMNT** bike computers (mainly the **BOLT v2**). The maps are generated by **WahooMapsCreator (WMC)** and carry extra information baked into the map file itself:

- **Wandrer.earth** data: unvisited roads (orange, dashed when unpaved) and achievement boundaries (subtle violet dashes);
- a **Squadrats** layer: outlines of the squares that are still unexplored;
- **customised POIs** (icons, and different icons depending on secondary tags).

---

## 1. Objective

### Why this project exists

Wandrer already provides Wahoo-ready exports, which I have used for years. The problem is that they force a choice:

- either the very simple Wandrer map style,
- or the colours and style of Wahoo's own maps or of WMC.

WMC maps are much prettier, more detailed, and they offer POIs. But Wandrer data cannot be added as a separate layer on top of a WMC map: it has to be merged into the map file itself.

### Goals

1. **No more choosing** between my Wandrer data and a nice, detailed map.
2. **Have POIs** on the map.
3. **Customise those POIs** (which ones, which icons, even depending on secondary tags).
4. **Cherry on the cake:** display the **Squadrats** (the unexplored squares).
5. **Bonus:** an easy graphical interface to do updates simply, and to **merge several Wandrer zones** downloaded separately.

### Resulting architecture

The first idea was to use Wandrer data *instead of* a normal map. That was dropped in favour of an **overlay inside the map file**:

```text
   OSM data ──► WMC (filter, split, MapWriter) ──┐
                                                 ├─► one .map.lzma per tile ──► ELEMNT BOLT
   Wandrer KMZ + Squadrats KML ──► converted ────┘
   to OSM-like ways (own IDs, own tags)
```

The Wandrer and Squadrats information is **not** a second layer loaded separately by the BOLT: it is **merged into the final `.map` file**, as extra ways with their own tags. The result is a **WMC map with extra information**, drawn by a custom VTM theme.

# 2. Technologies used

## WahooMapsCreator (WMC)

Open-source engine that generates the maps: `treee111/wahooMapsCreator` — https://github.com/treee111/wahooMapsCreator

It is a **pinned external dependency, not a fork**. It is installed with pip (`wahoomc 4.4.0` at the time of writing). It needs:

- Python;
- Osmium (`osmium-tool`);
- Osmosis with the MapWriter plugin (Java);
- GDAL (`ogr2ogr` **and** the Python `osgeo` module, from the same GDAL build);
- LZMA compression.

WMC declares only `packaging` as a Python dependency but also imports `shapely`, `geojson` and `requests`, so these must be installed too.

The basic command works:

```bash
python3 -m wahoomc cli -xy 136/88
```

WMC stores all its data in `~/wahooMapsCreatorData` (download, config, tiles, output). This location is hard-coded; a symlink can be used to relocate it.

## Osmium

Used for filtering OSM data, extracting areas, merging files, converting OSM XML ↔ PBF and inspecting data. Tested version: `osmium 1.16.0` (libosmium 2.17.1).

## Osmosis

Osmosis (with the MapWriter plugin) is called by WMC to produce the `.map` files. WMC handles it; it is not something this project installs or calls directly.

## Mapsforge format and VTM theme

The `.map` files use the mapsforge binary format. The BOLT v2 renders them with a **VTM** theme (`vtm-elemnt.xml`). The theme decides what is drawn, at which zoom and with which style.

# 4. Wahoo maps

A map generated by WMC produces, per tile:

```text
<x>/<y>.map.lzma
<x>/<y>.map.lzma.17      (empty marker file)
```

For the BOLT v2, files go to:

```text
ELEMNT-BOLT/maps/tiles/8/<x>/<y>.map.lzma
```

Tiles are **zoom-8 slippy-map tiles** (x/y). Around Munich:

```text
135/88   135/89   136/88   136/89
```

Example, tile `136/88`:

```text
west  = 11.25
east  = 12.65625
south = 47.989922
north = 49.008535
```

Copying to the Bolt is manual (file by file, never replacing a whole folder, after backing up `maps/tiles/8`). The themes live in `maps/vtm-elemnt/`.

## ELEMNT ROAM v1 (tested October 2026 on a borrowed device, tile 136/88)

- Tiles are `maps/tiles/8/<x>/<y>.map.gz`: the same mapsforge binary (v3) as our `.map.lzma`, only gzip-compressed (file name inside the gzip: `<y>.map`). No `.17` marker. The factory tiles held OSM data from 2015.
- VTM rendering is switched on by an **empty file `cfg_BHomeActivity_VtmMaps` at the device root** (next to `maps` and `factory`). Our `maps/vtm-elemnt/vtm-elemnt.xml` and `icons/` are then used, with the theme's "ROAM" style layer (no building fills there).
- A restart is enough to read new tiles; empty `maps/temp` after changing the theme. adb was not needed (`am broadcast ... BMapManager.PURGE` / `RELOAD_MAP` kept in reserve).
- `highway=wandrer` gave a blank map (see section 7). A ROAM theme variant using pure magenta `#FF00FF` also gave a blank map with a tile that works with the usual theme: avoid it.
- Not a problem: tiles of 26–28 MB gzipped (36–39 MB unpacked), the 8-digit transparent colour, dashes.
- Few screen colours (our orange looks beige), POIs crowd the map at 500 m; free space on that device was about 250 MB, enough for a few tiles only.
- Ideas for later: ROAM colours, fewer POIs at wide zoom, copy with `adb push` from the page.

# 5. How WahooMapsCreator works

```text
OSM PBF
   │
   ▼
osmium filter  (keeps only the tags listed in tags-to-keep.json)
   │
   ▼
split per zoom-8 tile
   │
   ▼
merge with land/sea polygons (Osmosis)
   │
   ▼
Osmosis MapWriter  (only encodes tags declared in the tag-mapping XML)
   │
   ▼
.map
   │
   ▼
LZMA
   │
   ▼
.map.lzma
```

Two steps silently **drop** anything unknown: the osmium filter (tag not in `tags-to-keep.json`) and MapWriter (tag not declared in the tag-mapping XML). The final rendering on the device is then decided by the VTM theme.

# 6. VTM theme and POIs

The BOLT v2 uses the VTM theme `vtm-elemnt.xml` with its icons in `maps/vtm-elemnt/icons/`. The repository version is `themes/vtm/vtm-elemnt.xml` (based on WMC's POI theme, `device_themes/vtm_theme_poi`).

POIs tested successfully:

```text
amenity=cafe, amenity=drinking_water, amenity=fuel, amenity=toilets,
shop=bakery, shop=bicycle, railway=station
```

Custom icons are plain SVG files declared in the theme:

```xml
<m v="toilets">
    <symbol src="icons/toilets_blue.svg" symbol-percent="150"/>
</m>
```

The BOLT accepts new icon file names without problem.

## POI depending on a secondary tag (test done: toilets)

A POI can look different depending on a second tag. Tested on toilets:

| OSM tags | Icon | Colour |
|---|---|---|
| `amenity=toilets` + `fee=yes` | `toilets_red.svg` | red |
| `amenity=toilets` + `fee=no` | `toilets_green.svg` | green |
| `amenity=toilets`, no `fee` tag (NA) | `toilets_blue.svg` | blue |
| `amenity=toilets` + `access=customers` or `private` | *hidden* | — |

Theme rule:

```xml
<m v="toilets">
   <m k="access" v="-|customers|private">
      <m k="fee" v="yes"><symbol src="icons/toilets_red.svg" symbol-percent="150"/></m>
      <m k="fee" v="no"><symbol src="icons/toilets_green.svg" symbol-percent="150"/></m>
      <m k="fee" v="-|yes|no"><symbol src="icons/toilets_blue.svg" symbol-percent="150"/></m>
   </m>
</m>
```

In VTM, `v="-|a|b"` means "not a and not b", and it **includes the case where the key is absent** (upstream WMC uses the same trick with `access v="-|private"`). The test was validated on the BOLT.

For this to work the secondary tags must also reach the map: `fee` and `access` were added to `tags-to-keep.json` and to the POI tag-mapping XML (`config/tag-wahoo-poi-wandrer.xml`). They are not yet in the classic (non-Wandrer) tag files.

# 7. Keeping custom tags: three places

Every new tag must be declared in **three** places, otherwise it silently disappears:

1. the **tag-mapping XML** (`config/tag-wahoo*.xml`) — MapWriter;
2. **`config/tags-to-keep.json`** — the osmium filter;
3. the **VTM theme** (`themes/vtm/vtm-elemnt.xml`) — the drawing rules.

Tags used by the project:

```text
wandrer=visited | unvisited   (+ surface=unpaved)    (no highway tag, see below)
wandrer=boundary
squadrat=big | small                               (ways without highway tag)
fee=yes|no, access=customers|private               (POI sub-tags)
```

`build_tiles.py` copies the repository's config files into WMC's config folder (`sync_config()`), so the repository is the single source of truth.

History: when the Squadrats layer was first added, `squadrat` was missing from `tags-to-keep.json` and the layer vanished without any error. The symptom is tile files whose size does not change.

The tag-mapping rules for Wandrer look like this:

```xml
<osm-tag key="wandrer" value="unvisited" zoom-appear="10" />
```

Early proof of concept: before such a rule existed, the `.map.lzma` was about 1.7 KB; after it, 56 KB — proof that the data now reached MapWriter.

History: the Wandrer roads used to carry `highway=wandrer` as well. It was dropped in October 2026: an ELEMNT ROAM v1 shows a blank map as soon as a tile holds this unknown highway value, and the theme only matches on `wandrer=*` (the boundaries never had a highway tag).

# 8. Wandrer export

Wandrer exports a map as **KMZ** (a zip containing one KML), e.g. `wandrer-25-09-27.kmz` containing `wandrer-bike-25-09-26.kml`. The KML uses these styles:

```text
#Traveled   #Untraveled   #UntraveledUnpaved   #achievementBoundary
```

Example content of one export (Munich, September 2026): about 59,700 traveled, 59,600 untraveled and 29,800 untraveled-unpaved lines, plus boundary polygons. Exports cover an arbitrary area, often larger than one Wahoo tile.

---

# 9. KMZ → OSM conversion

The KMZ cannot be used by WMC directly, so every `LineString` becomes an OSM-like way:

```text
KML placemark #Untraveled  → way: wandrer=unvisited
KML placemark #UntraveledUnpaved → same + surface=unpaved
#achievementBoundary rings → wandrer=boundary (each ring split in 2 open ways)
```

Node IDs start at 50,000,000,000 and way IDs at 9,000,000,000 so they never clash with real OSM IDs. Traveled roads are **not written by default** (they would only add weight).

**Principle kept:** Wandrer stays an *independent geometry* on top of the WMC data. It is never matched or merged with OSM ways, because Wandrer and WMC may use different OSM snapshots (changed geometries, split/merged ways, tag and ID differences, tolerances). Matching would bring many problems and no benefit.

## Slimming and merging

- **Radius filter:** unvisited roads are kept only within 250 m of traveled roads (paved or not), using a 50 m grid.
- **Chain merging** of consecutive segments (up to 1000 points) and **Douglas–Peucker** simplification (1.5 m).
- **Several exports are merged:** a segment's key is its coordinates rounded to 1e-6 (direction ignored). The **newest export wins** on overlap: an old segment that is absent from a newer export is removed only if that export **replaces** it (its roads lie on the old one, >= 90 % of the points within a few metres: Wandrer redrew the road, or it was ridden and is now a traveled segment with another geometry). Absence alone is not enough, even inside the export's boundaries: an export lists the boundaries of a much larger area than the roads it contains (the first version removed by boundary and lost about 40,000 valid unvisited roads).

# 10. Squadrats

The Squadrats KML contains the **explored** squares, dissolved into polygons with holes (layers: `squadrats` = zoom 14, `squadratinhos` = zoom 17; yard/uber are ignored).

Squares are plain **OSM slippy-map tiles** (Web Mercator), so everything is done in integer tile indices — no geometric error. One big square (z14) contains 8×8 small squares (z17).

What is drawn is the outline of the **unexplored** squares (each edge once; collinear runs merged):

- big level: a band of N squares around the explored area (default 3);
- small level, scope option: `explored-big` (default: every unexplored small square inside an explored big square), `band`, or `both`.

Style (the Bolt line width does not scale with zoom): small squares dashed `6,6`, width 1.4; big squares solid, width 1.6; red (`#E03030`, `#FF6060` in dark mode). Zoom: big from 11, small from 14. On the BOLT the small squares are visible at the 500 m scale and the big ones at 5 km. Cost: about 1 % of extra tile size.

The Squadrats export is global: the most recent one is used.

# 11. Wandrer style

The overlay must stay recognisable while keeping the underlying WMC road visible.

- unvisited roads: **orange**, solid;
- unvisited **and unpaved**: orange, **dashed**;
- achievement boundaries: **subtle violet dashes** (an earlier idea was green).

Bolt scales in practice: 200 m usually, 100 m in town, 50 m to search; roads at 500 m are essential, at 1 km useful.

# 12. Explored and dropped: Wandrer vector tiles and Chrome extension

The official Wandrer Chrome extension ("Wandrer Map Overlay") displays Wandrer data as an independent overlay using MVT vector tiles (layers such as `missing_segments`, `missing_segments_local`, attributes like `way_id`, `unpaved`, `foot`, `bike`, `never`). They can be inspected with `ogrinfo`.

**Decision: not used.** The endpoints are internal/authenticated and the extension's code is proprietary. The user's own KMZ export is a simpler and explicit source. A dynamic integration could be reconsidered later, after checking Wandrer's terms of use.

# 13. Target architecture (GUI)

Decision: a **local web page** (small Python server + HTML/Leaflet), rather than tkinter; wrapped as a standalone app at the very end.

```text
GUI (browser)
   │  choices: tiles/regions, Wandrer options, Squadrats, POI rules
   ▼
configuration (settings file)
   │
   ├─► OSM / WMC (base maps)
   └─► Wandrer KMZ + Squadrats KML ─► conversion ─► merge
                    │
                    ▼
            WMC / MapWriter ─► .map.lzma ─► copy to BOLT
```

Planned features:

- base maps by country/sub-region, or by clicking tiles; Wandrer/Squadrats updates with tiles deduced automatically;
- Simple/Pro toggle (Pro reads export contents: traveled/untraveled/unpaved/boundaries; radius);
- boundaries option for everyone (greyed out with a message if absent from the export);
- Squadrats band width = any integer (default 3) when in band scope;
- remembered export folders; preview of Wandrer boundaries and big Squadrats only;
- a POI rules table that generates tag-mapping, `tags-to-keep.json` and theme rules;
- `install.sh`; every setting stays dynamic so the GUI can drive it.

Mixing bike/foot exports is the user's business (warning only).

# 17. Principles to keep

1. **Wandrer is an overlay in a WMC map**, never a replacement for it.
2. **Do not match Wandrer geometries with OSM ways.**
3. **A new tag goes in three places** (tag-mapping, `tags-to-keep.json`, theme).
4. **Check the data before the style:** if the tag is not in the PBF sent to MapWriter, changing the theme does nothing.
5. **One `.map.lzma` per tile** — the BOLT does not load a separate transparent layer.
6. **Use the right tile** and copy file by file.
7. **Personal data stays out of the repository.**
8. **Everything configurable stays dynamic** for the future GUI.

# 18. Glossary

**WMC** — WahooMapsCreator.
**VTM** — vector map engine/theme format used by the BOLT for rendering.
**MapWriter** — Osmosis plugin that writes mapsforge `.map` files.
**Wandrer** — Wandrer.earth, tracking which roads you have travelled.
**Untraveled / UntraveledUnpaved** — roads not yet travelled (and unpaved) in the Wandrer export.
**Achievement boundary** — limit of a Wandrer achievement area.
**Squadrats / Squadratinhos** — big (zoom 14) and small (zoom 17) OSM-tile squares of the Squadrats game.
**Tile** — zoom-8 Wahoo tile `x/y`, e.g. `136/88`.
**POI** — point of interest.
**KMZ** — zip archive containing the KML exported by Wandrer.
**MVT** — Mapbox Vector Tiles, used by Wandrer's web extension.

# 19. Final vision

The result is a **WMC map** — detailed, pretty, with POIs — **plus extra information visible at a glance**:

```text
   normal WMC map content (roads, POIs, land use…)

   road not yet travelled (Wandrer)        ─────  orange
   road not travelled and unpaved          - - -  orange dashed
   achievement boundary                    - - -  violet, subtle
   unexplored Squadrats square (big)       ─────  red
   unexplored Squadratinho (small)         - - -  red dashed
   POI with variants (toilets)             free = green, paid = red, unknown = blue
```

The aim is a BOLT that is **aware of my Wandrer and Squadrats history** without giving up the readability and richness of a WMC map.
